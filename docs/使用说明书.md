# Nota 使用说明书

## 1. 产品概述

Nota 是一套**本地运行、可追溯、可编辑的知识笔记工具**。它接收 PDF、Word、PPT、图片、文本和录音等学习材料，将内容转化为结构化笔记，并保留原始材料中的页码、文本片段、图片或音频时间定位。

Nota 运行在用户本机的 `127.0.0.1`。笔记、上传原件、版本记录和导出文件默认保存在本机；调用文本模型、视觉模型或录音转写服务时，相应材料会发送至用户自行配置的模型服务。

## 2. 启动与访问

### Windows

双击项目根目录的 `Nota.lnk` 或 `Nota.cmd`。首次启动会创建 Python 虚拟环境并安装依赖，随后浏览器打开：

```text
http://127.0.0.1:7860/
```

启动失败时，双击 `start.cmd` 查看实时输出，或查看：

```text
runtime/nota.stderr.log
```

### macOS / Linux

首次执行：

```bash
chmod +x setup.sh Nota.sh
./setup.sh
./Nota.sh
```

## 3. 配置模型

打开页面右上角的 **模型设置**，填写模型名称、兼容 OpenAI Chat Completions 的 API URL 和 API Key。

| 角色 | 作用 | 配置建议 |
| --- | --- | --- |
| 默认模型 | Cards、Writer、Vision 等关键步骤的兜底 | **强烈建议使用 Claude 或 GPT** |
| Outline | 大纲组织、章节规划与审校 | 可单独使用 DeepSeek 等低成本模型 |
| ASR | 录音转写 | 配置 Paraformer 或兼容服务 |

默认模型承担材料理解、知识抽取、正文写作和复杂图文分析，直接影响笔记质量。Outline 的任务偏向结构规划，可独立使用低成本模型控制调用成本。

已保存的 API Key 不会返回到网页端；页面只显示该角色是否已配置。

## 4. 创建笔记

### 4.1 添加材料

在左侧“材料与目标”区域选择或拖入文件。支持：

- 文档：PDF、DOCX、PPTX、TXT、Markdown；
- 图片：JPG、PNG、WebP、BMP、TIFF 等；
- 录音：WAV、MP3、M4A、FLAC、AAC、OGG、OPUS、WMA 等。

可同时上传多份材料，并为每份材料设置：

- **材料类型**：个人笔记、课堂 PPT、论文、教材、习题、会议材料、普通材料或自动识别；
- **材料角色**：主要内容、补充资料或风格参考。

### 4.2 设置目标

可设置笔记目标、详略程度、个人要求、个人写作风格、是否保留来源图片、是否为手写材料、视觉识别方式、最大处理页数以及音频说话人区分。

例如：

- 要求：`保留算法步骤，重点解释易错点`；
- 风格：`短句、箭头串联、例子单独列出`。

### 4.3 开始生成

点击“生成笔记”后会出现生成提示。复杂材料，例如超过 70 页的 PPT、图片很多的 PDF、多份材料组合上传或较长录音，可能显著增加耗时，甚至因解析或模型响应限制而失败。

建议先按章节或主题拆分复杂材料，再分批处理。通常生成需要几分钟；复杂材料可能需要 30 分钟或更久。生成会在后台继续进行，可在“最近任务”中查看进度。

## 5. 阅读、追溯与编辑

### 5.1 阅读笔记

生成完成后可在以下区域工作：

- **阅读与编辑**：查看正文、引用按钮和章节内容；
- **复习问题**：查看基于笔记生成的复习提示；
- **逐字稿**：校对录音转写；
- **版本历史**：比较版本和恢复历史版本。

### 5.2 原始依据

正文中的来源按钮会打开“原始依据”面板。面板展示来源文件名、页码或音频时间位置、提取文本、关联图片，以及 PDF 原件预览或“打开原始材料”链接。

来源信息帮助用户核对笔记内容，不代表生成内容可替代人工判断。

### 5.3 编辑和修订

- 点击“编辑正文”可直接修改某一节并保存为新版本；
- 点击“对话修订”，输入如“压缩为考前速记，保留公式”的要求，系统会基于原始材料重写该节；
- 音频逐字稿校对后，可根据校对稿重新生成笔记；
- 恢复旧版本会创建新版本，不会覆盖既有版本历史。

## 6. 历史、重试与导出

### 最近笔记

左侧“最近笔记”保留最近更新的 10 份笔记。点击可重新打开、继续编辑或导出。删除一份笔记会删除它及其版本历史，**不会删除原始上传材料**。

### 最近任务和重试

“最近任务”默认折叠。任务失败、中断或取消后，可选择“重试未完成步骤”。系统会尽量复用已完成的解析和知识提取结果，避免从头处理。

### 导出

可导出：Markdown + 图片包、HTML、PDF、纯 Markdown 或逐字稿；也可选择是否保留来源标注。PDF 包含排版、公式和图片处理，通常比 HTML 或 Markdown 更耗时。

## 7. 数据、隐私与限制

- 运行数据、上传材料、缓存和导出产物保存在 `object/data/`；
- 不要将真实 API Key、私密材料或录音提交到 Git；
- 调用模型或 ASR 时，对应材料会发送给用户配置的服务商；
- 大型、图像密集或长音频材料建议预先拆分；
- 若 PDF 导出失败，可选择 HTML 或 Markdown。

## 8. 常见问题

**双击 Nota 后没有打开页面**：运行 `start.cmd`，检查虚拟环境、端口 7860、依赖安装情况及 `runtime/nota.stderr.log`。

**上传录音后提示未配置 ASR**：在模型设置中填写 ASR 的 API Key、API URL 与模型名。

**生成很慢或失败**：减少单次材料数量、页数和图片量，或降低详略程度；之后从“最近任务”选择“重试未完成步骤”。

**原始材料没有显示**：先点击“打开原始材料”确认原件存在；PDF 内嵌预览不兼容时，可在新标签页打开原文件。
